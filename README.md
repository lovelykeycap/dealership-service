# Dealership

Backend автосалона для продажи автомобилей, подбора комплектаций, записи на тест-драйв и складского учёта.

## Возможности

- Заказ автомобиля из наличия или в выбранной комплектации, назначение менеджера и управление статусами до выдачи.
- Конфигуратор с проверкой совместимости деталей и расчётом цены относительно базовой комплектации.
- Каталог моделей и автомобилей с фильтрами по цене, марке, модели и характеристикам комплектации.
- Запись на тест-драйв и управление списком доступных для него моделей.
- Учёт запчастей и остатков, резервирование автомобилей и обработка заказов на сборку.
- Авторизация через Keycloak: клиент, менеджер, администратор склада и администратор системы. Клиент видит и отменяет только свои заказы.

## Архитектура

| Сервис | Ответственность | REST API |
| --- | --- | --- |
| `order-service` | Заказы, конфигуратор, тест-драйвы, просмотр автомобилей в наличии | `http://localhost:8080` |
| `storage-service` | Каталог, складские остатки, заказы на сборку | `http://localhost:8082` |

У каждого сервиса своя PostgreSQL и миграции Liquibase. Общие модули содержат настройки JWT, контракты событий и gRPC.

После отметки об оплате `order-service` сохраняет событие в Outbox вместе со статусом заказа. Фоновый обработчик отправляет его в RabbitMQ. Склад резервирует автомобиль или списывает комплектующие и возвращает результат согласования. Обработчики учитывают повторную доставку событий, а `traceId` связывает записи в логах.

Список автомобилей в наличии и отдельный автомобиль доступны через `GET /api/v1/cars` и `GET /api/v1/cars/{id}`. Эти запросы получают данные склада по gRPC с таймаутом; при недоступности склада API возвращает `503`. Данные каталога для оформления заказов и тест-драйвов запрашиваются по REST.

## Стек

Java 21, Spring Boot 3, Spring Data JPA, PostgreSQL 16, Liquibase, Spring Security, Keycloak, RabbitMQ, gRPC, Protobuf, MapStruct, Gradle, Docker Compose. Тесты используют JUnit 5, Mockito и Testcontainers.

## Локальный запуск

Нужен Docker Compose. Образы сервисов собираются с JDK 21 внутри Docker.

1. Поднимите Keycloak и его БД:

   ```bash
   docker compose up -d keycloak
   ```

2. Откройте [Keycloak](http://localhost:8081), войдите с `admin` / `admin`. Создайте realm `dealership`, клиент для получения JWT и пользователей с realm-ролями `USER`, `MANAGER`, `WAREHOUSE_ADMIN`, `ADMIN`. Конфигурация realm в репозитории отсутствует.
3. Соберите и запустите остальные сервисы:

   ```bash
   docker compose up --build -d
   ```

Swagger UI: [заказы](http://localhost:8080/swagger-ui.html) и [склад](http://localhost:8082/swagger-ui.html). Для запросов к API передавайте JWT из realm `dealership` в заголовке `Authorization: Bearer <token>`.

Compose содержит локальные учётные данные и использует `host.docker.internal` для доступа к Keycloak. При запуске без Docker Desktop настройте разрешение этого имени и `KEYCLOAK_ISSUER_URI` под своё окружение.
